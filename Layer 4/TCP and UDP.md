#layer4

## Definition
- session - exchange of data between two or more communicating devices
- forward acknowledgement - used to indicate the sequence number of the next segment the host expects to receive
## Context
- Functions of layer 4
	- provides transparent transfer of data between end hosts.
	- provides various services to applications:
		- reliable data transfer
		- error recovery
		- data sequencing
		- flow control
	- Provides Layer 4 addressing (port numbers)
		- Identify the application layer protocol (destination port from client to server)
		- provides session multiplexing
- session multiplexing 
	- addresses when sent from client
		- the src port is randomly chosen
		- the dst port is chosen to identify application layer protocol
	- addresses when sent from server
		- the src port is the application layer protocol
		- the dst port is the port of the client
	- You can have multiple sessions using different ports

## IANA (Internet Assigned Numbers Authority) port number ranges
- well-known port numbers = 0 - 1023
- Registered port numbers = 1024 - 49151
- Ephemeral/private/dynamic port numbers: 49152 - 65535
	- the random ports generated by the client uses this range

## Transmission Control Protocol (TCP)
- Connection Oriented
	- data exchange only begins only once the connection has been established. Two hosts communicate to establish a connection.
- Provides Reliable Communication
	- The destination host must acknowledge that it received each TCP segment.
	- If a segment isn't acknowledged, it is sent again.
- Provides Sequencing
	- Sequence numbers in the TCP header allow destination hosts to put segments in the correct order even if they arrive out of order.
- Provides flow control
	- the destination host can tell the source host to increase/decrease the rate that data is sent

- First Row (SD)
	- 16 bits = 65536 available port numbers for both src and dst
	- source and destination port are 16 bits each or 2 bytes each
- second row (S)
	- sequence number - 32 bits 
	- sequence number along with ACK number provide sequencing and reliable communication
- third row (A)
	- acknowledgement number (if ACK set) - 32 bits
	- sequence number along with ACK number provide sequencing and reliable communication
- Fourth Row (DR NCEUAPRSF W)
	- Data offset - 4 bits
	- Reserved - 3 bits
	- Flag bits - 9 bits
		- NS - 1 bit
		- CWR - 1 bit
		- ECE - 1 bit
		- URG - 1 bit
		- ACK - 1 bit - used to establish and terminate connections
		- PSH - 1 bit
		- RST - 1 bit
		- SYN - 1 bit - used to establish and terminate connections
		- FIN - 1 bit - used to establish and terminate connections
	- Window Size - 16 bits - used for flow control
- fifth row (CU)
	- Checksum - 16 bits
	- Urget pointer - 16 bits

### Connection Oriented
#### Three-Way Handshake - Establishing Connections
- SYN - client sends TCP segment with this flag set to 1
- SYN, ACK - server sends TCP segment with these flags set to 1
- ACK - client sends TCP segment with this flags set to 1
#### Four-Way Handshake - Terminating Connections
- Fin - client to server
- Ack - server to client
- Fin -  server to client
- ACK - client to server
- the connection is then temrinated

### Reliable Connections and Sequencing

#### Sequencing
- The Ack will always be seq + (window size)
- clients sends an arbitrary seq number (10)
- server sends an ack whose number is the client's seq number + 1 (11) and sends an arbitrary sequence number (50)
- the client sends a sequence number the same as the ack of the server. It then sends an ack that is +1 from the server sequence number (51)

| window-size = 1 | client<br>(c->s) | server<br>(c <- s) |
| --------------- | ---------------- | ------------------ |
| roundtrip 1<br> | seq 10<br>       | seq 50<br>ack 11   |
| roundtrip 2<br> | seq 11<br>ack 51 | seq 51<br>ack 12   |
| roundtrip 3<br> | seq 12<br>ack 52 | seq 52<br>ack 13   |

#### Reliable Connection
- If an acknowledge is not returned retransmission should occur

|                 | client<br>(c->s) | server<br>(c <- s) |
| --------------- | ---------------- | ------------------ |
| roundtrip 1<br> | seq 20<br>       | seq 50<br>ack 11   |
| roundtrip 2<br> | seq 11<br>ack 51 | -                  |
| roundtrip 3<br> | seq 11<br>ack 51 | seq 52<br>ack 13   |
#### Flow control
- TCP header's window size field allows more data to be sent before and acknowledgement is required.
- A sliding window can be used to dynamically adjust how large the window size is.
- window size is increased as much as possible until a segment is dropped, then the window size backs down to a more reasonable level, and slowly increases again

## (UDP)
- Is not connection-oriented
	- sending host does not establish a connection with the destination host before sending data. The data is simply sent
- does not provide reliable communication
		- When UDP is used, acknowledgements are not sent for received segments. If a segment is lost, USP has no mechanism to re-transmit it. Segments are sent 'best-effort'
- does not provide sequencing
	- There is no sequence number field in the UDP header. If segments arrive out of order, UDP has no mechanism to put them back in order
- does not provide flow control
	- UDP has no mechanism like TCP's window size to control the flow of data

## Comparing TCP and UDP
- There are some applications that use UDP, but provide reliability etc within the application itself
- Some applications use both TCP and UDP, depending on the situation

|                     | TCP                                      | UDP                                |
| ------------------- | ---------------------------------------- | ---------------------------------- |

| overhead            | more                                     | less                               |
| connection-oriented | connection-oriented                      | connetionless                      |
| reliable            | reliable                                 | unreliable                         |
| sequencing          | sequencing                               | No sequencing                      |
| flow control        | flow control                             | no flow control                    |
| applications        | Use for downloads,<br>file sharing, etc. | Used for VoIP,<br>live video, etc. |
